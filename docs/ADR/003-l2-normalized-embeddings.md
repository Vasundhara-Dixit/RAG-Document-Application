# ADR-003: L2-Normalized Embeddings for Cosine Equivalence

## Status
Accepted

## Context
Cosine similarity is the standard distance metric for text retrieval, but calculating cosine similarity on raw vectors involves computing vector magnitudes at query time ($A \cdot B / (\|A\| \|B\|)$). Inner product search ($A \cdot B$) in FAISS (`IndexFlatIP`) is significantly faster and hardware-vectorized.

## Decision
All dense embeddings generated by `Embedder` implementations must be L2-normalized ($v / \|v\|_2$) before insertion into FAISS and ChromaDB.
When vectors are unit length ($\|A\| = \|B\| = 1$), their dot product equals their cosine similarity:
$$\langle A, B \rangle = \cos(\theta)$$

## Consequences
- FAISS `IndexFlatIP` can be used directly without distance post-normalization.
- Any future embedding model integrated into the system must strictly apply L2-normalization.
